# Rule Lab decisions

- User requested a separate folder and preservation of teammates' versions. All
  changes are additive under Filip's existing `eval/` lane. No main-server hook,
  shared UI edit, dependency/config edit or fixture/cache refresh is included.
- Use the existing Q1 Lifecycle proposal, not a competing accounting agent. Keep
  authority, grounding, hard-control and conflict checks in the real engine.
- Evaluate regression boundaries only after every existing gate passes. An agent
  author never receives even a simulated application of its candidate.
- Freeze the oracle independently of each draft. Removing a scope or condition
  must not silently loosen the tests meant to constrain it.
- Restrict the initial pack to unsigned compensation vouchers. Arbitrary policy
  families and automatic test synthesis need separate reviewed oracles.
- Test applicability as well as monetary outcomes: signed consent is already
  protected in the engine, so that mutation is a scope failure, not a payout bug.
- Temporary SQLite only; no rule confirmation, persistent ledger, paid LLM, or
  production data. Evidence is exported on request by the browser or CLI stdout.
- Passing means ready for human review. It never means approved or certified.
- Source fingerprints bind the report to relevant code and fixed inputs. They
  are local integrity checksums, not cryptographic attestations.
